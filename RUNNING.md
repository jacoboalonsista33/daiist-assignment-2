# Solar panel project

## Run the submitted dashboard

```bash
uv sync --frozen
uv run python main.py app
```

Open http://127.0.0.1:7860. The app loads weights/best.pt and artifacts/;
it never trains at startup. Restore the saved thresholds with the reset button.

## Training pipeline

```bash
uv run python main.py train
```

Supply ROBOFLOW_API_KEY through the environment or an ignored .env file.
The script downloads susan-ifblr/panel-solar-bw945 version 1, preserves the
original files, creates a detection copy, trains, evaluates both baselines,
selects the policy on validation, and exports dashboard artifacts. Settings
are in pipeline_config.json. The production configuration is 30 epochs,
640 pixels, batch 16. CUDA is selected when available; otherwise CPU is used.
Set TRAIN_DEVICE=mps explicitly to use a supported Apple GPU.

On Colab, retain its GPU-enabled PyTorch and install the project's dependencies
with pip instead of uv sync. Load the key from Colab Secrets into the environment
before running `!python main.py train`. Avoid retaining notebook models in GPU
memory while launching a separate training process. Save results outside the
runtime before disconnecting.

Source: Susan, Panel Solar v1, CC BY 4.0:
https://universe.roboflow.com/susan-ifblr/panel-solar-bw945/dataset/1

## Interpretation

The dashboard simulates routing recommendations and creates no external tickets.
Confidence is not a calibrated probability. Pass does not certify a healthy panel.
Costs assume correct human review and 10% production prevalence. Incident costs
are included; photo-review staffing is labeled separately from incident handling.
Actual split counts and prevalence-adjusted expected counts are separate.
Bird_drop test metrics are N/A because no ground-truth objects exist in test.
